# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

This plan operationalizes the technical specification `spec/spec-design-semibold-weight.md` (v1.1, 2026-08-20) into phased, vertically verifiable execution tasks. The feature adds **SemiBold** (CSS weight 600) and **SemiBold Italic** variants to the Fantasque Sans Mono family by replicating the shipped Medium pattern: a standalone one-shot Python script generates the `.sfdir` sources, which are committed as canonical source files. The existing `Makefile` wildcard discovery, build scripts, CI/CD pipelines, and packaging workflows then compile, validate, and distribute the new variants automatically — **zero modifications to the CON-07 zero-touch set**.

The distinguishing discipline of this feature versus Medium is that **no stroke value is a free constant**: the reference stroke is established empirically by the §4.3 calibration contract (composite AND gate), and the `font.weight` assignment is proven by the §4.2.1 acceptance gate. Per the clarification report (`docs/audit/clarification-report-plan-semibold-weight-2026-08-20.md`, Review Iteration 1, 96/100), **both the calibration and the empirical gates execute in GitHub Actions CI — the same path used to build the Medium font — NOT on the maintainer's local machine and NOT pre-commit**. The feature branch is committed and pushed first; the gates then run in CI; visual QA sign-off follows before merge. All such evidence MUST be recorded verbatim in the `Execution Results` section of this plan (Spec §4.2.1, §6).

## 1. Requirements & Constraints

### Requirements (from Spec §3)

- **REQ-01**: A single standalone Python script `Scripts/generate-semibold-source.py` SHALL generate the SemiBold `.sfdir` sources. It SHALL be a standalone copy of the shipped Medium generator with SemiBold constants — the Medium artifact must not be modified.
- **REQ-02**: The script SHALL accept exactly two positional arguments — input `.sfdir` and output `.sfdir`. Any other count SHALL print usage to stderr and exit non-zero.
- **REQ-03**: The script SHALL detect italic input via the basename prefix `FantasqueSansMono-Italic` and produce SemiBold Italic; italic angle (-11.0) and OS/2 italic flag SHALL be preserved from the source Italic.
- **REQ-04**: The script SHALL apply a single-pass embolden via `changeWeight(stroke, "LCG", 0, 0, "retain")`, where `stroke` is established per the §4.3 calibration contract.
- **REQ-05**: Every generated glyph SHALL have its advance width strictly set to exactly `1060` em-units.
- **REQ-06**: The script SHALL call font-level `removeOverlap()` and `simplify()` after `ChangeWeight`. Per-glyph `intersect()` cleanup is forbidden (Medium plan Dead-End #11).
- **REQ-07**: The generated source SHALL have `os2_weight = 600` and weight name `SemiBold`; SFNT name entries SHALL follow Spec §4.2.
- **REQ-08**: The script SHALL be functionally idempotent — repeated runs produce identical contour geometry and metrics.
- **REQ-09**: The script SHALL never modify the input source in place.
- **REQ-10**: Generated sources SHALL be committed to a temporary feature branch (not `master`); merged to `master` only after maintainer visual QA sign-off.
- **REQ-11**: The script SHALL be retained for reproducibility but SHALL NOT be part of the standard build pipeline.

### Constraints (from Spec §3)

- **CON-01**: No modifications to the zero-touch set are required for SemiBold compilation, CSS generation, or packaging.
- **CON-02**: The reference stroke SHALL be selected per the §4.3 calibration contract before sources are committed; no stroke value may be hard-coded without calibration.
- **CON-03**: All four variant permutations (`Normal`, `LargeLineHeight`, `NoLoopK`, `LargeLineHeight-NoLoopK`) SHALL apply to SemiBold and SemiBold Italic via the existing `Makefile` wildcard.
- **CON-04**: SemiBold SHALL be compiled into TTF, OTF, WOFF, WOFF2, and SVG outputs in the appropriate `Variants/` subdirectories.
- **CON-05**: SemiBold SHALL be released additively as part of the next regular release bundle — no standalone release.

### Guidelines (from Spec §3)

- **GUD-01**: The reference stroke targets the 55–70 em-unit band (~1.6×–2.1× the Medium stroke of 34 em-units); 45 em-units is the hard floor.
- **GUD-02**: `os2_weight` SHALL be assigned before `font.weight` (OS/2 WeightWidthSlopeOnly precedence); `font.weight` SHALL be set explicitly to kill stale `Regular`/`Book` inheritance.
- **GUD-03**: Watch for preferred-family records (SFNT IDs 16/17) as a side effect of metadata assignment (Medium TASK-104 precedent: none for the documented order).

### Traceability Anchors (PRD)

- **FR-01**: SemiBold source generation script (P0) — standalone copy, calibration rule, width 1060, `removeOverlap`/`simplify`, OS/2 600.
- **FR-02**: SemiBold Italic source generation (P0) — same script, italic basename detection, preserve italic angle and flag.
- **FR-03**: Canonical sources & commit discipline (P0) — commit to feature branch, merge only after visual QA sign-off.
- **FR-04**: Automatic build pipeline integration (P0) — Makefile wildcard, four permutations, five output formats.
- **FR-05**: CSS `@font-face` declaration with `font-weight: 600` (P1).
- **FR-06**: Packaging and distribution — `zip-all-variants`, `custom-build.yml`, additive release (P1).
- **FR-07**: SFNT metadata correctness (P1).
- **FR-08**: `validate-font` compatibility under the maintainer baseline exception (P1).
- **FR-09**: Nerd Fonts patching compatibility (P2, optional; external dispatch validation).
- **GH-001..GH-008**: PRD user stories (generation, italic, build, family grouping, CSS, visual QA, packaging, CI) — each mapped to Spec AC-001..AC-010.

## 3. Alternatives

- **ALT-001**: `interpolateFonts()` between Regular and Bold masters (unmerged `origin/feature/multi-weight-poc` branch). Rejected — the Regular and Bold sources have non-matching point/contour topology, which rules out master-based interpolation (Spec §10).
- **ALT-002**: Modify the `Makefile` to list SemiBold sources explicitly. Rejected — the existing `SOURCES=$(wildcard Sources/FantasqueSansMono*.sfdir)` wildcard already discovers the new sources; touching the Makefile violates the zero-touch mandate (CON-07).
- **ALT-003**: Expose the stroke as a third CLI argument to speed up calibration runs. Rejected — Spec §4.1 locks the CLI error contract at exactly two positional arguments (REQ-02); calibration runs edit the `STROKE_WIDTH` constant per candidate, as the §8 structure defines it.
- **ALT-004**: Automatic manual per-glyph counter fixes when calibration fails. Rejected — Spec §4.3 rule 5 mandates escalation to a maintainer decision at or above the 45 em-unit floor; manual fixes occur only on explicit maintainer request (Spec §9 "Ask first" boundary).

## 7. Risks & Assumptions

### Risks

- **RISK-001 (Counter clogging on dense glyphs)**: The SemiBold stroke is ~1.6×–2.1× the Medium stroke (34 em-units), raising clogging risk on `e`, `a`, `s`, `@`, `%`, `&`, `8`, `#` — Medium recorded 252 upright / 465 italic self-intersections. **Mitigation**: §4.3 calibration composite AND gate (upright AND italic counters AND two-sided neighbor gate), `counter_type="retain"` (lowercase), mandatory visual QA on BOTH specimens (TASK-022, scoped to `Normal`), explicit escalation at/above the 45 em-unit floor. **Impact**: High. **Tasks affected**: TASK-004, TASK-022.
- **RISK-002 (`font.weight` binding rejects or normalizes `"SemiBold"`)**: The FontForge Python binding's accepted value set is undocumented; Medium/Bold exercised standard names only, and the Italic source really carries `Weight: Book`. **Mitigation**: §4.2.1 empirical gate with five artifacts per run on BOTH invocations (TASK-006, executed in CI), built-TTF/OTF evidence, escalation to a maintainer/spec-update decision — no silent naming fallback. Residual: the CI FontForge version is **unpinned** (deliberately, matching Medium; CI modification is out-of-scope per Spec §1.1) — the version is recorded with the evidence and the reproducibility risk is **accepted**. **Impact**: Medium-High. **Tasks affected**: TASK-006.
- **RISK-003 (Advance width drift)**: `ChangeWeight` may alter advance widths, breaking the monospace grid. **Mitigation**: REQ-05 enforces explicit re-set to 1060; TEST-004 audits in VERIFY gates (TASK-008, TASK-024). **Impact**: Low. **Tasks affected**: TASK-001, TASK-005, TASK-024.
- **RISK-004 (Zero-touch / Medium regression)**: An implementation slip could touch the CON-07 set or the Medium artifact. **Mitigation**: AC-010 merge-base diff audits (TASK-014, TASK-020(e), TASK-024(e)); script is a standalone copy, never an edit of the Medium generator. **Impact**: Low-Medium. **Tasks affected**: TASK-001, TASK-014, TASK-024.
- **RISK-005 (CI evidence scope confusion)**: `custom-build` compiles one selected variant and omits other-formats/CSS; `build-make.yml` evidences the Makefile path only. Claiming AC-005 or AC-007 from CI evidence would produce false sign-offs. **Mitigation**: explicit Phase 3 coverage note; AC-005 SFNT content pinned to TASK-006/TASK-015, AC-005 OS grouping and AC-007 pinned to TASK-022. **Impact**: Medium (evidence integrity). **Tasks affected**: TASK-017, TASK-018, TASK-020.

### Assumptions (Extracted from Spec §1.2)

- **ASSUMPTION-001**: The generated sources are committed to version control; the generation script is run manually once by the developer/maintainer and is never executed in the CI pipeline (same contract as the Medium feature). The empirical calibration/gates READ from CI-built artifacts, but the script itself is not part of CI. **Tasks affected**: TASK-010 (flagged High Risk). **Risk**: Low (accepted design decision).
- **ASSUMPTION-002**: The reference stroke used in the Spec §8 code sample is **60 em-units** (mid-point of the candidate grid 50/60/70). The final value is NOT a free design choice: it must be established empirically via the §4.3 calibration contract and locked before the sources are committed. **Tasks affected**: TASK-004, TASK-022 (flagged High Risk). **Risk**: Medium.
- **ASSUMPTION-003**: The new unit-test module mirrors the structure of `tests/test_generate_medium_source.py` (fake `fontforge` module; the exact added test count is determined at implementation). The full suite — the 83-test baseline plus the new SemiBold generation tests — must pass with zero failures before the Code phase is complete. **Tasks affected**: TASK-002, TASK-003. **Risk**: Low-Medium.
