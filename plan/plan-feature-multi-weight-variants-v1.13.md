# Implementation Plan: Multi-Weight Font Variants for Fantasque Sans Mono

![Status: Planned](https://img.shields.io/badge/status-Planned-lightgrey)

## Introduction

This plan outlines the step-by-step execution to implement Multi-Weight Font Variants (Medium, SemiBold, Light, ExtraBold) for Fantasque Sans Mono via FontForge master harmonization and linear interpolation. The execution strictly preserves legacy source files (CON-001) and integrates with the existing Custom Build Workflow. Stretch weights (Light 300, ExtraBold 800) only ship via the release upstream pipeline after core weights pass visual review (E10) — Custom Build produces core weights only.

## 1. Requirements & Constraints

- **REQ-H01 to H06**: Master Harmonization & Visual Invariants
- **REQ-I01 to I07**: Multi-Weight Interpolation, Auto-Hinting, and Metric Preservation
- **REQ-B01 to B06**: Build Pipeline Integration (Pre-processing in Stage 1)
- **REQ-D01 to D04**: Output Formats, File Naming, and Release Packaging
- **REQ-S01 to S05**: Specimen Sheet & Visual QA Validation
- **CON-001**: Legacy Code Preservation (build.py, fontbuilder.py, features.py MUST NOT be modified)
- **CON-002**: Workflow A — FontForge Interpolation Only
- **CON-003**: Linear Interpolation Only — only linear interpolation via `font.interpolateFonts()`; no optical correction
- **CON-004**: No Stroke Modification — `font.changeWeight()` or automated stroke modification algorithms MUST NOT be used — only interpolation between harmonized masters
- **CON-005**: Vertical Metrics Freeze (Ascent, Descent, LineGap MUST NOT change)
- **CON-006**: No Italic instances generated for new weights (Faux Italic fallback)
- **CON-007**: GitHub Actions Free-Tier — build MUST run on free-tier runner (`ubuntu-latest`) with time limit 360 minutes
- **CON-008**: FontForge Python 3 Bindings — all scripts MUST be compatible with default Ubuntu 26.04 bindings + `future` shim
- **GUD-001**: Deterministic Build — two runs with identical input MUST produce byte-identical font files
- **GUD-002**: Fail-Fast on Critical Error — interpolation failures with heavy contour distortion (self-intersection, closed counter) MUST halt the pipeline with non-zero exit code and diagnostic message. *Enforcement (r3 K8): via fail-fast loop `validate_interpolation.py --threshold T_final --fail-fast` per core weight (TASK-4.2) — the driver does NOT duplicate detection logic (sufficient to propagate FontForge errors; see TASK-0.7).*
- **GUD-003**: Progress Logging — Build log MUST display progress per stage
- **GUD-004**: Partial Success Tolerance — Stretch weight failure does NOT fail the entire build
- **SEC-001**: No User Data — no user data is collected, stored, or transmitted
- **SEC-002**: Scoped Token — GitHub Actions token has limited `contents: write` permission scoped to the fork where the workflow runs

## 3. Alternatives

- **ALT-001 (Workflow B - UFO/fontmake)**: Using the modern UFO v3 ecosystem and `fontmake`. Rejected for V1 because it changes the repository structure too radically; will be explored in V2.
- **ALT-002 (Single-file Variable Font)**: Creating a variable font with `wght` axis. Rejected for V1 because it requires full migration to UFO; V1 focuses only on static weights.
- **ALT-003 (Stroke modification algorithms)**: Using automatic thick/thin algorithms such as `font.changeWeight()`. Rejected because it damages the asymmetry of "wibbly-wobbly" (counter space and handwritten detail).

## 4. Dependencies

- **DEP-001**: FontForge Python 3 API (`fontforge` python module) on ubuntu:26.04.
- **DEP-002**: Type Designer team (Designer A & Designer B) to perform substantial manual harmonization (~140-240 hours).

## 7. Risks & Assumptions

- **RISK-001**: Harmonization takes a very long time (bottleneck) due to massive manual work.

Risk only relevant for *release upstream pipeline* (definition: manual/isolated execution by upstream maintainer outside CI — see TASK-5.4; Custom Build does not produce stretch weight — E10); mitigated via *gate check* pass/fail: fail → excluded from V1 → V2 (*partial success*, GUD-004).
- **ASSUMPTION-001**: `Scripts/features.py` is assumed to be deterministic and idempotent, so it can be called multiple times without changing results (validated by E0.1).
